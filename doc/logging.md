# 日志中心

## 页面使用

登录后从侧栏进入「日志中心」（`/logs`）。页面只返回当前账号的记录，支持：

- 时间范围、级别和分类筛选；默认最近 7 天；
- 按参考编号、操作标识、资源编号、错误码搜索；
- 每页 50 条，上一页、下一页；
- 展开元数据详情、复制参考编号；
- 导出当前页为 JSON，不是导出全部筛选结果。

从功能启用后开始记录，不自动导入旧的控制台日志或历史模型运行记录。筛选统计对应整组查询结果，而不是当前页。

## 记录范围

`ActivityLog` 保存结构化元数据：时间、级别、来源服务、分类、操作、状态、参考编号、关联资源、耗时、重试次数、HTTP 状态及错误码。

- 操作记录：注册/登录成功、退出，以及已认证请求的新增、修改、删除等操作和请求失败。
- 对话执行：模型运行成功、失败、停止及耗时。
- 后台任务：文件解析、会议分析、记忆整理、PPT 生成的完成、重试和失败。
- 系统事件：后台恢复、日志清理等运行异常。无法确认用户归属的记录 `userId` 为空，不通过个人日志接口返回。

不记录请求体、查询字符串、密码、Cookie、Authorization、对话正文、文件内容或未经处理的异常消息。输出到控制台的用户标识经过哈希处理。工具参数与历史 `AgentEvent` / `ToolExecution` 属于既有执行存储，不由日志页面公开。

健康检查、日志查询和正常的 GET 查询不写操作日志，避免轮询产生大量噪声。登录失败无法可信绑定到当前用户，不显示到任何个人账号的日志中。

## 权限与查询

`GET /api/logs`、`GET /api/logs/:id` 均需要登录。用户范围取自服务端校验后的 JWT，忽略客户端提交的 `userId`；详情也按用户归属查询，跨账号请求返回 404。当前未开放管理员全局查询或服务器文件读取接口。

列表支持 `level`、`category`、`q`、`from`、`to`、`limit` 和 `cursor`。日期使用含时区的 ISO 8601；分页上限 100。按时间与 ID 倒序进行游标分页，同一时间的记录也不会重复翻页。参考编号来自服务器，不能由请求头覆盖。HTTP 响应头 `X-Request-Id` 与异常响应 `traceId` 对应请求日志；对话与后台任务使用运行或任务编号。

## 保留与部署

新增迁移：`202610030001_activity_logs`。先执行 Prisma generate / migrate deploy，再构建并重启 API 和 Worker。Windows `start.cmd start` 会应用待执行迁移；已经运行的服务需重启才能加载新代码。

`LOG_RETENTION_DAYS` 默认 30，支持 1–365，配置无效时使用 30。该值需一致注入 API 和 Worker。API 启动时及每小时清理过期 `ActivityLog`；查询也独立应用截止时间。清理仅作用于日志表，不删除会话、文件和其他业务数据。

写日志采用最多 500 条在途写入的缓冲。数据库异常或缓冲已满时，业务请求不因此失败；每分钟最多输出一次脱敏写入告警。正常关闭会等待写入完成，强制结束进程可能丢失尚未写入的记录。因此它是运行排错日志，不是保证不丢失、不可篡改的合规审计账本。

## 原始服务日志

Windows 原始 stdout/stderr 继续保存在 `.local/logs/`。API、Worker 和 Web 在启动新进程前，将非空旧日志移动到 `.local/logs/archive/`，附带时间戳，避免重启覆盖。

数据库日志的 30 天保留策略**不适用于原始服务日志与归档文件**。原始文件未做运行中按大小轮转，也不会自动删除旧归档；长期部署需配置宿主机或容器的日志轮转和磁盘监控。Docker 部署沿用容器 stdout/stderr。

原始日志可能包含历史版本或依赖库输出，不应直接上传或对普通账号开放。
